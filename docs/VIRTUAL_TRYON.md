# Виртуальная примерка: отчёт

## Что реализовано сейчас
1. **Композиция на аватаре (работает без ИИ, без сети).** Нарисованный кодом женский 2D-аватар (`AvatarRenderer`) + PNG вещей, размещённые по
   зонам (`GarmentPlacementEngine`: верх, низ, платье, верхняя одежда, обувь, сумка, головной убор, шарф, украшения, аксессуары — у каждой свой слой z).
   Можно двигать вещь пальцем, масштабировать, поворачивать, скрывать; результат сохраняется (история `TryOnRecord`, превью образа) и экспортируется.
   Это **наложение изображений, а не генеративная примерка**; ткань не драпируется, перекрытия и силуэт не корректируются.
2. **Интерфейс генеративной примерки** (`VirtualTryOnProvider`, `TryOnGenerationController`, `TryOnRepository`): прогресс (время ожидания), отмена,
   тайм-аут, ошибки, повтор, результат сохраняется только после успеха. По умолчанию подключён `UnavailableTryOnProvider` — честно сообщает, что модель не подключена.
3. **`HTTPTryOnProvider`** — клиент к *вашему* серверу (Профиль → ИИ-примерка). Секретов в приложении нет. **Не проверялся с реальным сервером.**

## Выбранная модель-кандидат: FASHN VTON v1.5
Сведения получены поиском в этом сеансе (карточка Hugging Face, GitHub, пост авторов):
- Лицензия весов по карточке модели: **Apache-2.0**; авторы называют её первой коммерчески пригодной открытой VTON.
- ~972 млн параметров, веса ~2 ГБ; парсер человека (~244 МБ) докачивается автоматически.
- Заявленные требования: ~8 ГБ VRAM минимум, работает на потребительских GPU (RTX 30xx/40xx), ~5 с на H100; рекомендован GPU.
- Принимает фото человека + фото одежды (в т.ч. flat-lay), категории вроде tops (по примеру авторов).

**Не проверено:** лицензия кода (в GitHub указано «See LICENSE» — файл не открывался), лицензии парсера и зависимостей (onnxruntime и др.),
качество на **иллюстрированном аниме-аватаре** (модель обучена на фото реальных людей — совместимость может быть плохой; это нужно проверять экспериментально),
поведение с аксессуарами/обувью. Другие известные открытые модели (например, IDM-VTON, CatVTON, OOTDiffusion), по моим сведениям из памяти, имеют некоммерческие лицензии (CC BY-NC-SA) —
**в этом сеансе не проверялись**, до использования в публичном продукте перепроверьте.

## Как запускать (бесплатно ли?)
Открытая модель ≠ бесплатный хостинг. На iPhone она не запустится. Варианты:
- **Свой ПК с NVIDIA GPU ≥ 8 ГБ VRAM** + сервер в домашней сети — бесплатно по деньгам (кроме электричества). iPhone должен быть в той же сети (разрешён http в локальной сети: `NSAllowsLocalNetworking`; для интернета используйте https).
- Аренда GPU или бесплатные тарифы облачных ноутбуков — **платно/нестабильно/с ограничениями**, не рекомендуется делать постоянной зависимостью.
- В GitHub Actions генерацию **не запускать** (нет GPU, нарушает назначение workflow).

## Протокол сервера (то, что ожидает `HTTPTryOnProvider`)
`POST <url>` `multipart/form-data`: `avatar` (PNG базового аватара), `categories` (через запятую, id категорий приложения: `tops,bottoms,dresses,outerwear,shoes,...`),
`garment_0`, `garment_1`, … (PNG, порядок соответствует `categories`). Ответ `200` с телом-изображением (PNG/JPEG).
Любой другой код или не-изображение → ошибка в интерфейсе. Тайм-аут запроса — 240 с.

Эскиз сервера (**не запускался**; API `TryOnPipeline` взят из примера в карточке модели, сверяйтесь с её README):
```python
# pip install fastapi uvicorn pillow python-multipart  + зависимости fashn-vton-1.5
from fastapi import FastAPI, Request
from fastapi.responses import Response
from PIL import Image; import io
from fashn_vton import TryOnPipeline
app = FastAPI(); pipe = TryOnPipeline(weights_dir="./weights")
MAP = {"tops": "tops", "outerwear": "tops", "bottoms": "bottoms", "dresses": "one-pieces"}  # проверьте допустимые категории
@app.post("/tryon")
async def tryon(request: Request):
    form = await request.form()
    person = Image.open(io.BytesIO(await form["avatar"].read())).convert("RGB")
    cats = [c for c in form["categories"].split(",")]
    for i, cat in enumerate(cats):
        if cat not in MAP: continue                       # обувь/аксессуары моделью не поддерживаются
        g = Image.open(io.BytesIO(await form[f"garment_{i}"].read())).convert("RGB")
        person = pipe(person_image=person, garment_image=g, category=MAP[cat]).images[0]
    buf = io.BytesIO(); person.save(buf, "PNG"); return Response(buf.getvalue(), media_type="image/png")
```
Ограничения: модель рассчитана на одежду (верх/низ/платья); обувь, сумки, украшения и головные уборы остаются режимом композиции.

## Различия режимов
| | Композиция | Генеративная |
|---|---|---|
| Работает офлайн | да | нет (нужен сервер с GPU) |
| Качество посадки | плоское наложение PNG | возможна реалистичная посадка (на фото), на иллюстрации не проверено |
| Обувь/аксессуары | да | нет |
| Стоимость | 0 | оборудование/аренда GPU |

## Рекомендуемый план проверки (вам)
1. Развернуть модель на GPU-ПК. 2. Прогнать 10–20 вещей на аватаре (сохраните через «Экспорт» аватар без одежды). 3. Если результат плох — добавить второй «базовый персонаж» (более реалистичный)
только для экспериментального режима, не заменяя основной аватар. 4. Проверить `LICENSE` кода и всех зависимостей до любого публичного релиза.
