# Архитектура

```
AmyWardrobe/
  App/            точка входа, TabView; если БД не открылась — экран с объяснением (данные не удаляются)
  Core/           ImageStore (контентно-адресуемое хранилище), ImageCache, SystemIO (Фото/камера/шаринг/экспорт), AppError
  Domain/         SwiftData-модели, CollageDocument (структура коллажа), Taxonomy, ColorPalette, AppSettings
  Data/           WardrobeFilter, сервисы (Wardrobe/Outfit/Collage/Folder/GarbageCollector), StylistEngine, ZipArchive, BackupService
  DesignSystem/   токены, кнопки, карточки, чипы, FlowLayout, TagEditor
  Features/       Home, Wardrobe, Collages (редактор + CollageRenderer), Outfits, VirtualTryOn, Backup, Profile
```

## Данные
- **SwiftData** (`WardrobeItem`, `Folder`, `CollageProject`, `Outfit`, `TryOnRecord`), `AmySchemaV1` + `AmyMigrationPlan` (этапов пока нет; все поля с дефолтами).
- **Изображения** — файлы `Application Support/AmyWardrobe/Images/<sha256>.<ext>` (оригинал без перекодирования), миниатюры в `Thumbs/` (PNG при наличии альфы, иначе JPEG).
  В БД хранятся только имена файлов (устойчивые ссылки). Одинаковые файлы не дублируются.
- **Политика снимков:** коллаж и образ хранят *собственные ссылки* на файлы изображений, а не только id вещи. Переименование/удаление вещи не ломает проекты.
  Файлы удаляются только `GarbageCollector`, если на них нет ссылок ни из вещей, ни из коллажей, ни из образов, ни из истории примерок; файлы моложе 10 минут не трогаются;
  при невозможности разобрать хоть один документ уборка пропускается.
- **Коллаж** — `CollageDocument` (JSON в `documentData`): размер полотна, фон, массив объектов снизу вверх. Объект: центр, базовый размер, `scale`, `rotation`, текст/рамка/ссылка на файл.
  Координаты документа отделены от экранных: редактор показывает документ с коэффициентом `s`, поэтому ориентация/размер экрана не влияют на проект.
- **Автосохранение:** debounce 0,7 с после изменений + при уходе приложения в фон + при закрытии редактора; запись файлов атомарна (`.atomic`).
- **Экспорт** — `CollageRenderer` (Core Graphics) рендерит документ в отдельный контекст; тот же код рисует слои текста/рамок в редакторе, поэтому экспорт совпадает с экраном.

## Формат резервной копии v1 (ZIP, метод STORE)
```
manifest.json  { formatVersion, appVersion, createdAt, counts, files:[{path,size,sha256}], warnings }
data.json      { items, collages, outfits, folders, tryOns, settings }
images/<sha256>.<ext>
```
Проверки при импорте: ZIP/CRC, версия (`> 1` отклоняется), список файлов манифеста (допустимые пути, размер, SHA-256, имя = хэш содержимого, читаемость изображения),
декодирование `data.json` (обязательные поля), предупреждения о недостающих изображениях. Слияние: по `id`; запись заменяется, только если в копии `updatedAt` новее — повторный импорт ничего не дублирует.
Изменение БД — одна транзакция (`save`, при ошибке `rollback`). Лимит ZIP без ZIP64: < 4 ГиБ и < 65 000 файлов (при превышении — понятная ошибка).
Добавление формата v2: расширить `BackupManifest`/`BackupPayload` и добавить миграцию v1→v2 в `inspect`.

## Производительность
Миниатюры 400 px с дисковым кешем; `NSCache` (500 шт., 96 МБ, очищается при memory warning); декодирование через ImageIO `CreateThumbnailAtIndex` вне главного потока;
`LazyVGrid`; фильтрация — чистые функции по массиву из `@Query`. Рассчитано на 500–2000 вещей, **на реальном устройстве не измерялось**.

## Известные слабые места дизайна
- Поиск/фильтрация линейные (без индексов) — на 5000+ вещей может понадобиться предикатный `FetchDescriptor`.
- `AppSettings` декодируется целиком: при добавлении полей нужен `decodeIfPresent`, иначе старые настройки сбросятся к умолчанию.
- Аватар — векторная графика, нарисованная кодом: годится как рабочая база, а не как финальная иллюстрация.
