# AmyWardrobe

Личный цифровой гардероб для iPhone: вещи, свободный редактор коллажей, образы, композиция на 2D-аватаре,
резервные копии. Интерфейс на русском, стиль Lavender Aesthetic. Все данные хранятся локально, аккаунты, сервер и подписка не нужны.

> **Честный статус проекта (прочитайте).** Весь код написан в среде **без Xcode, Swift и доступа к сети**.
> Поэтому **ни сборка, ни тесты, ни запуск на устройстве здесь не выполнялись** — не проверялся ни один компилятором символ.
> Первая сборка на GitHub Actions вполне может показать ошибки компиляции; исправление — обычная часть работы
> (см. «Если сборка упала»). Подробности — `docs/STATUS.md`.

## Что внутри

| Вкладка | Возможности |
|---|---|
| Главная | приветствие, быстрые действия, недавние вещи, избранные образы, последние коллажи, подборка сочетаний по правилам (не ИИ) |
| Гардероб | сетка с ленивой загрузкой миниатюр, поиск, фильтры (категория, цвет, сезон, тег, избранное), сортировка, пакетные действия, добавление из галереи / камеры / «Файлов» / буфера обмена |
| Коллажи | свободный редактор (перемещение, масштаб, поворот, слои, текст, рамки, фон, undo/redo, автосохранение), папки, теги, избранное, дублирование, экспорт PNG/JPEG |
| Образы | из вещей, из коллажа (отдельная сущность), замена вещей, превью, примерка, экспорт |
| Профиль | мерки и параметры аватара, резервные копии, настройки, лицензии |

Не реализовано (явно): ручная обрезка фото, автоматическое удаление фона, погодные рекомендации, уведомления,
реальная генеративная ИИ-примерка (есть заменяемый интерфейс и клиент к *вашему* серверу), iCloud-синхронизация,
тёмная тема проверена только в токенах дизайн-системы, UI-тесты. См. `docs/STATUS.md`.

## Репозиторий

```
project.yml                   # описание проекта для XcodeGen (из него создаётся .xcodeproj)
AmyWardrobe/                  # исходный код приложения (App, Core, Data, Domain, DesignSystem, Features, Resources)
AmyWardrobeTests/             # XCTest
scripts/                      # выбор Xcode, выбор симулятора, сборка IPA
.github/workflows/build-ios.yml
docs/                         # SIDELOADLY, VIRTUAL_TRYON, ARCHITECTURE, STATUS
```

`.xcodeproj` намеренно **не хранится** в репозитории: его создаёт XcodeGen (`project.yml`) — так нет рукописного `project.pbxproj`.

## Публикация на GitHub (с компьютера)

```bash
cd AmyWardrobe
git add -A && git commit -m "Initial commit"      # репозиторий уже инициализирован локально
# создайте ПУСТОЙ репозиторий на github.com (без README), затем:
git remote add origin https://github.com/<ваш-логин>/AmyWardrobe.git
git push -u origin main
```
Без Mac/терминала: на github.com → New repository → Upload files, загрузите содержимое папки (включая скрытую `.github`).
Затем **Actions** → *Build AmyWardrobe IPA* → **Run workflow**.

## Получение IPA

1. GitHub → вкладка **Actions** → последний успешный запуск *Build AmyWardrobe IPA*.
2. Внизу страницы, в блоке **Artifacts**, скачайте `AmyWardrobe-ipa-build<N>` (ZIP). Распакуйте — внутри `AmyWardrobe-1.0.0-build<N>.ipa`.
3. IPA **не подписан** — подписывает Sideloadly при установке. Инструкция: `docs/SIDELOADLY.md`.

Workflow: проверка исходников → выбор Xcode (последний стабильный на `macos-26`) → XcodeGen → тесты на симуляторе →
сборка Release для `iphoneos` без подписи → упаковка `Payload/*.app` в `.ipa` → артефакт. При ошибке сохраняются логи и `.xcresult`.

## Открыть в Xcode (нужен Mac)

```bash
brew install xcodegen
xcodegen generate
open AmyWardrobe.xcodeproj
```
iOS 17.0+, Swift 5 language mode. Хранилище — **SwiftData** (выбрано: нативно для SwiftUI, не требует сторонних библиотек,
есть `VersionedSchema`/`SchemaMigrationPlan`; все поля имеют значения по умолчанию, чтобы добавлять поля легковесной миграцией).

## Резервное копирование и восстановление

Профиль → **Резервные копии**. Создаётся ZIP (`manifest.json` + `data.json` + `images/…`) с SHA-256 каждого файла.
Сохраните его в «Файлы» (в т.ч. iCloud Drive). Это **ручной экспорт**, а не синхронизация между устройствами.
Восстановление: Профиль → Резервные копии → «Восстановить из файла». Архив сначала полностью проверяется
(формат, версия, контрольные суммы, обязательные поля, пути) и только потом объединяется с данными; повторный импорт не создаёт дубликатов;
при ошибке текущие данные остаются нетронутыми.

## Обновление приложения без потери данных

Ставьте новую сборку **поверх** старой тем же Apple ID и тем же Bundle ID (Sideloadly так и делает) — данные приложения сохраняются.
Не удаляйте приложение перед обновлением. Перед любым обновлением и **каждые 7 дней** (срок бесплатной подписи) делайте резервную копию.
Если приложение всё же удалено: установите заново → Профиль → Резервные копии → Восстановить.

## Если сборка упала

Скачайте артефакт `diagnostics-build<N>` (логи + `TestResults.xcresult`) или откройте лог шага в Actions. Типичные причины:
ошибка компиляции Swift (самая вероятная при первом запуске, т.к. код не компилировался), недоступное имя симулятора (скрипт выбирает его сам),
смена версии Xcode на runner'е (`scripts/select_xcode.sh`, переменная `MAX_XCODE_MAJOR`). Скопируйте текст ошибки — её можно исправить точечно.

## Лицензии

Сторонних библиотек нет (только фреймворки Apple). XcodeGen (MIT) используется только при сборке. Шрифты — системные.
Файл лицензии самого проекта не добавлен: выберите его сами перед публикацией.
